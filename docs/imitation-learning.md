# 모방학습(Imitation Learning)

> 작성 2026-09-10. 개념 정리 문서.
> 관련: `docs/mpc-act-rtc.md`(청킹의 배경), `docs/policies.md`(구현된 정책들).

---

## 1. 정의

**보상함수 대신 전문가의 시연으로 정책을 학습하는 것.**

강화학습은 "무엇이 좋은 상태인가"를 점수로 정의해야 한다.
모방학습은 그 정의를 포기하고 **"사람이 한 대로 하면 잘한 것"** 으로 대체한다.

---

## 2. 왜 로보틱스에서 이게 주류가 됐나

### 보상함수를 쓸 수 없다
"수건을 개라"의 비용함수를 수식으로 적을 수 없다. 억지로 적으면
엉뚱한 방향으로 최적화된다(reward hacking). 조작 태스크 대부분이 이렇다.

### 실물 로봇에서 탐색 비용이 파괴적이다
RL은 무작위 행동으로 시작해 시행착오로 배운다. 시뮬에서는 공짜지만
실물에서는 **로봇이 부서지고, 수백만 번 시도할 시간이 없다.**

### 시연은 모으기 쉽다
사람이 리더 암으로 조종하면 관절 궤적이 **그대로 액션 라벨**이 된다.
별도 라벨링이 필요 없다. Open X-Embodiment 200만 궤적,
DROID 92K 궤적이 이렇게 쌓였다.

---

## 3. 계열

| 방식 | 원리 | 성격 |
|---|---|---|
| **Behavioral Cloning (BC)** | (관측 → 액션) 지도학습 | 가장 단순. **VLA는 사실상 전부 여기** |
| Inverse RL (IRL) | 시연에서 **보상함수를 역추론**하고 그걸로 RL | 원리적으로 깔끔하나 비쌈 |
| Adversarial (GAIL 등) | 판별자가 전문가/정책을 구분, 정책은 속이려 함 | GAN 구조 |
| **DAgger** | 정책을 굴리다 막히면 **전문가가 그 자리에서 교정** | 온라인. 아래 4절 참조 |

현대 VLA는 **거의 전부 BC**다. 이유는 단순하다 — **확장이 되기 때문이다.**
시연만 모으면 되고, 데이터가 늘수록 좋아지고, 웹 사전학습과 섞기 쉽다.

---

## 4. BC의 근본 문제: 오차 누적

**학습 분포는 전문가 궤적 위에만 있다.** 정책이 조금이라도 벗어나면
**학습 때 본 적 없는 상태**에 놓이고, 거기서 더 큰 실수를 하고,
더 멀리 벗어난다. 복리로 커진다.

이걸 **covariate shift** 또는 **compounding error**라 부른다.
고전적 결과로, 단순 BC의 오차는 에피소드 길이 T에 대해 **O(T²ε)** 로 커진다.
한 스텝 오차율이 작아도 긴 태스크에서는 치명적이다.

### 대응의 계보

**(a) DAgger (2011)** — 정책을 실행시키다가 **정책이 방문한 상태에서
전문가에게 정답을 묻는다.** 학습 분포를 정책의 분포 쪽으로 끌어온다.
오차 경계를 O(Tε)로 낮춘다. 대가는 **전문가가 계속 붙어 있어야** 한다는 것.

**(b) 액션 청킹 (2023)** — 한 스텝씩이 아니라 k스텝을 한 번에 예측해
**유효 의사결정 횟수를 1/k로 줄인다.** 오차가 쌓일 기회 자체를 줄인다.
`docs/mpc-act-rtc.md` 참조.
이론적 분석도 나와 있다 —
[Action Chunking and Exploratory Data Collection Yield Exponential Improvements
in Behavior Cloning (2507.09061)](https://arxiv.org/pdf/2507.09061).

**(c) 데이터 다양성** — 일부러 벗어난 상태에서 복귀하는 시연을 섞는다.
LeRobot 문서가 "같은 태스크를 여러 위치에서, 위치당 10개씩" 권하는 것도
같은 맥락이다.

**(d) 사람 개입 RL** — HIL-SERL. 아래 6절.

## 5. 두 번째 문제: 멀티모달성

**사람은 매번 똑같이 하지 않는다.** 컵을 왼쪽으로 돌아 잡아도 되고
오른쪽으로 돌아 잡아도 된다. 시연에 두 방식이 섞여 있을 때
**평균을 내는 회귀 모델은 정면충돌하는 경로를 낸다.**

`docs/policies.md`의 액션 표현 표가 이 문제에 대한 답들이다.

| 대응 | 방식 |
|---|---|
| CVAE latent (ACT) | style 변수 `z`로 흡수, 추론 시 0 고정 |
| 이산 토큰 | 분포를 범주형으로 표현 |
| 확산 / flow matching | 멀티모달 분포를 직접 모델링 |

대형 VLA가 flow matching으로 수렴한 가장 큰 이유가 이것이다.

## 6. 세 번째 문제: 전문가를 넘어설 수 없다

BC의 목표는 **시연을 재현하는 것**이다. 정의상 전문가보다 잘할 수 없고,
**실패 데이터가 없어서** 무엇이 나쁜지 배우지 못한다.
스스로 개선할 신호가 없다.

여기서 RL이 다시 들어온다.

- **HIL-SERL** (LeRobot의 `sac`) — 사람이 개입해 교정하면서 RL을 돌린다.
  BC로 초기화하고 실물에서 개선하는 구조
- **리워드 모델** — SARM, TOPreward, Robometer.
  "잘한 행동"을 평가하는 모델을 따로 학습한다.
  `docs/vla-lineage.md` §4 참조

**BC로 바닥을 깔고 RL로 올린다**는 것이 현재의 구도다.
LLM의 사전학습 → RLHF와 구조가 같다.

## 7. LeRobot에서의 모방학습

파이프라인이 그대로 4단계다.

```
lerobot-teleoperate  →  사람이 리더 암으로 조종
lerobot-record       →  시연을 LeRobotDataset으로 기록
lerobot-train        →  BC 학습 (act / diffusion / smolvla / pi0 ...)
lerobot-rollout      →  정책 자율 실행
```

`lerobot-rollout`의 `--strategy.type`에 계열이 드러난다.

| strategy | 성격 |
|---|---|
| `base` | 순수 자율 실행 |
| `episodic` | 에피소드 단위, 사이에 리셋 |
| `sentry` | 연속 기록 + 자동 업로드 |
| `highlight` | 링 버퍼, 키 입력으로 저장 |
| **`dagger`** | **사람 개입 데이터 수집** — 4절 (a)의 구현 |

문서의 데이터 수집 권고도 4절·5절과 직접 대응한다 —
**에피소드 50개 이상, 변형당 10개**, 카메라 고정, 파지 방식 일관,
그리고 **변형을 한꺼번에 늘리지 말 것.**
분포를 넓히되 통제된 방식으로 넓히라는 뜻이다.

---

## 8. VLA가 바꾼 것

전통적 모방학습은 **태스크 하나에 정책 하나**였다.
VLA는 여기에 두 가지를 더했다.

1. **언어 조건화** — 같은 정책이 지시문에 따라 다른 일을 한다
2. **웹 사전학습** — 로봇 데이터에 없는 상식·물체 지식을 VLM 백본에서 가져온다

그래도 **학습 방식 자체는 여전히 BC**다. 손실함수는
"시연된 액션을 맞춰라"이고, π0.5가 웹 VQA를 섞은 것도
보상을 도입한 게 아니라 **BC의 입력 분포를 넓힌 것**이다.

> 다만 LIBERO-Plus가 지적한 결함 중 **"언어를 사실상 안 본다"** 는
> 이 구조와 무관하지 않다. 시연 데이터에서 지시문은 대체로 태스크당 하나로
> 고정돼 있어서, 시각 정보만으로 액션을 맞출 수 있으면
> 모델이 언어를 무시해도 손실이 줄어든다.
